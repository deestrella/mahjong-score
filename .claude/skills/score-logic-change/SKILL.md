# 点数・役ロジックを直すときの手順

このページの価値は「出した点数が正しいこと」に尽きます。1か所直すと別の手の点数が変わりやすい(分解の選び方・符の切り上げ・役の複合が絡む)ので、次の順で進めます。

## 1. 採用ルールに触れないか確かめる

CLAUDE.md の「採用しているルール」は持ち主が決めたものです。依頼がこれを変える内容なら、コードを書く前にユーザーに確認してください。

- 切り上げ満貫なし(4翻30符・3翻60符は 7,700 / 11,600 のまま)
- 連風牌の雀頭は 4 符
- 役満の複合は 13 翻で頭打ち(ダブル役満なし)
- 天和・地和・人和・流し満貫は未対応
- 喰いタンあり、赤ドラは枚数で手入力

たとえば「ダブル役満にしたい」「切り上げ満貫を入れたい」は確認が要ります。「三色同刻が付かない」のような明らかなバグはそのまま直して構いません。

## 2. 直す前に、再現する手を `tests/cases.json` に足す

先にテストを足して `npm test` で **FAIL になることを確かめてから**直します。失敗を見ないまま直すと、テストが本当にバグを捉えているか分かりません。

### 書き方

```json
{ "name": "三色同刻・三暗刻", "hand": "222m222p222s55z789s", "melds": "", "rw": 0, "sw": 1, "way": "ron", "expect": "8,000点" }
```

- `hand`: 鳴いていない牌すべて。**最後の 1 枚があがり牌**として扱われます(テストはあがり牌を選び直しません)。待ちの形(単騎・嵌張・辺張・両面・双碰)は最後の牌で決まるので、狙った待ちになる並びにしてください。
- `melds`: 鳴いた面子をスペース区切り。`666z` ポン、`345m` チー、`5555s` 明槓、`(1111s)` 暗槓。
- 牌の記法: `m` 萬子 / `p` 筒子 / `s` 索子 / `z` 字牌(1東 2南 3西 4北 5白 6發 7中)。`0` は赤5ですが、テストでは普通の 5 と同じ扱いです。
- `rw` 場風(0東 1南)、`sw` 自風(0東=親 1南 2西 3北)、`way` は `ron` か `tsumo`。
- `expect`: 画面の答え欄に**含まれる**文字列。ロンは `3,900点`、子のツモは `800・1,600`、親のツモは `2,600オール`(「点」は付きません) のような形です。迷ったら既存のケースの出力(`npm test` の `→` の右側)を見て形を合わせます。
- `name`: 何を確かめる手かが分かる日本語。

### 期待値は手で計算する

`expect` は**アプリの出力を写さず**、符と翻を自分で数えて出してください。アプリの出力を写すと、バグごと正解として固定してしまいます。ケースを足すときは、会話の中で内訳を示します。

```
副底20 + 門前ロン10 + 中の暗刻8 + 嵌張2 = 40符
役: 中1 + 一気通貫2 = 3翻 → 子 40符3翻 = 5,200点
```

### どの手を足すか

直したい手 1 つだけでなく、**境目の手**も足すと回帰を防げます。

- 役が付くべき手と、よく似ているが付かない手(例: 鳴いた一気通貫は 1 翻、門前は 2 翻)
- ロンとツモ、親と子で点数が変わる箇所
- 分解が複数ある手(高い方が選ばれるか)

## 3. 直す

`assets/app.js` の地図は CLAUDE.md にあります。あわせて気をつけること:

- UI に出る文言(役名・エラー・符の内訳ラベル)は日本語の です・ます調で短く。
- `archive/` は旧版なので触りません。
- 写真で分からない役(リーチ・一発・ドラなど)は `ex` / `exList()` / `applyHan()` 側です。今のテストはここを操作しないので、ここを変えたらブラウザで画面を確かめてください(`/run` が使えます)。テストランナーをこの部分まで広げたいときは、ユーザーに相談してから `tests/run.mjs` を拡張します。

## 4. `npm test` をすべて通す

足したケースだけでなく、**既存のケースがすべて OK** であることを確かめます。既存のケースが FAIL になったら、それは直したことの副作用です。期待値を書き換えて通すのではなく、どちらが正しいか手計算で確かめ、既存の期待値が間違っていた場合だけユーザーに伝えたうえで直します。

クラウドのセッションで `Cannot find package 'playwright'` が出たら、インストール済みの Playwright をつないでから実行します(`node_modules/` は git に入りません)。

```bash
mkdir -p node_modules && ln -sfn "$(npm root -g)/playwright" node_modules/playwright
```

手元のパソコンでは `npm install` → `npx playwright install chromium` です。

## 5. 報告する

最後に次をまとめて伝えます。

- 何が原因で、どう直したか
- 足したケース(名前と、手計算の内訳)
- `npm test` の結果(件数と、すべて成功したか)

公開は `main` への push だけで反映されます。push はユーザーに頼まれたときだけ行ってください。
